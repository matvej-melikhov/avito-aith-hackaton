# Архитектура ядра

Извлечено из [03-platform.md](../../docs/03-platform.md), полное описание там.

```mermaid
flowchart TB
    subgraph IN["Адаптеры входа: откуда берём работу"]
        direction LR
        A1["GitHub, пул-реквест"]
        A2["Stepik"]
        A3["Google Docs"]
    end

    subgraph REQ["Требования: вводит координатор"]
        direction LR
        R1["Форма создания задания:<br/>текст для студента + критерии"]
    end

    subgraph CORE["ЯДРО: одинаково во всех сценариях"]
        direction TB
        C1["Разбор артефакта"]
        C2["Проверки кодом:<br/>формальные требования"]
        C3["Проверка моделью:<br/>по каждому требованию отдельно"]
        C4["Валидация цитат:<br/>цитаты нет в работе, вердикт отклонён"]
        C5["Сборка результата:<br/>вердикты, черновик обратной связи,<br/>сигнал об использовании ИИ"]
        C1 --> C2 --> C3 --> C4 --> C5
    end

    H(["ЧЕЛОВЕК<br/>подтверждает, меняет, отклоняет"])
    J[("Журнал:<br/>предложение, правка, финал")]

    subgraph OUT["Приёмники результата: куда уходит"]
        direction LR
        O1["Карточка ревьюера"]
        O2["Комментарий в пул-реквесте"]
        O3["Выгрузка в таблицу"]
        O4["Уведомления студенту"]
    end

    subgraph COORD["Координация: отключаемый модуль"]
        direction LR
        K1["Пул работ:<br/>ревьюер тянет сам"]
        K2["Сроки, штрафы,<br/>напоминания"]
        K3["Дашборд<br/>координатора"]
    end

    P{{"ПРОФИЛЬ СЦЕНАРИЯ:<br/>какие адаптеры, какие требования,<br/>нужна ли координация"}}

    IN --> CORE
    REQ --> CORE
    CORE --> H
    H --> J
    H --> OUT
    IN --> COORD
    COORD --> H

    P -. настраивает .-> IN
    P -. настраивает .-> REQ
    P -. включает или выключает .-> COORD
```


Как читать: синий поток посередине — ядро, не меняется никогда. Слева и справа — адаптеры, меняются под сценарий. Координация сбоку — отключаемый модуль. Человек стоит между ядром и любым выходом, обойти нельзя.

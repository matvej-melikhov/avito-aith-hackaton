# Шпаргалка к защите: ядро ИИ-проверки

Одна страница для того, кто рассказывает про ядро. Цифры из `docs/EVALS.md` и `docs/CALIBRATION.md`, прогоны 5–6 сентября 2026, публичный корпус Авито.

## Три фразы

1. Модель проверяет работу по каждому критерию задания и обязана подтвердить вердикт цитатой. Цитату сверяет код: не нашёл, значит балла нет и строка уходит ревьюеру.
2. Что можно проверить кодом, проверяется кодом: структура репозитория, наличие файлов и разделов, `go build` и `go vet`, а для Go-сервисов ещё и запуск в песочнице по сценариям из ТЗ: порт из `.env`, флаг `--port`, `/ping`, `/healthcheck`, остановка по сигналу, паника без базы, миграции goose, CRUD по кодам ответов. Модель получает это как факты, и факт запуска сильнее чтения кода.
3. Решение всегда за человеком. Сервис ничего не публикует, ревьюер меняет любой балл, каждое его решение пишется в журнал парой «предложено, решено».

## Что показать за три минуты

1. Ревьюер открывает работу: оценки уже стоят, у каждой цитата из файла со строками, сводка со стоимостью в рублях, блок сигнала об ИИ с вопросами для Q&A.
2. Ревьюер меняет один балл и правит черновик фидбека: показать, что модель предложила, а человек решил.
3. Студент до сдачи нажимает «ИИ-ревью»: короткий итог и грубые подсказки без цитат. Сказать вслух: это проверка полноты, а не оракул оценки, попытки ограничены.
4. Файл задания `prereview/assignments/system_design_lab1.json`: новое задание это файл настроек, ядро про курс не знает.

Запасной вариант, если стенд на сцене не поднимется: три ролика в `docs/demo/`, записаны на учебном стенде 6 сентября после слияния с интерфейсом Владимира, 30 кадров в секунду, 1920 на 1080. В репозитории лежат MP4 (5–7 МБ, вставляются в Keynote и Google Slides), гифки тех же роликов весят около 35 МБ и хранятся вне git.

- `student-self-review.mp4`: список домашек, работа вернулась на доработку, студентка смотрит критерии, загружает исправленный файл, пишет комментарий, запускает ИИ-ревью, видит итог и отправляет работу. Ожидание модели вырезано, длительность указана на карточке.
- `reviewer-assist.mp4`: ревьюер берёт Go-репозиторий из пула, разбор уже готов, дальше работа, сигнал об ИИ в процентах с причинами, критерии с цитатами из кода. Если балл ниже максимума, красным подсвечены фрагменты, которые его снизили, зелёным те, что подтверждают выполнение. Честная пометка: три основания сигнала в ролике написаны руками для показа (места в коде настоящие, формулировки наши), живой прогон на этой работе даёт 8% и «простые признаки не найдены». Остальное в ролике, включая запуск в песочнице (11 из 19 проверок), настоящий вывод сервиса.
- `coordinator-overview.mp4`: координатор смотрит обзор с показателями, домашки потока со статусами и баллами, готовит выгрузку, открывает задание (условие в Markdown и критерии) и пул проверок.

## Вопросы, которые зададут

**Почему не просто ChatGPT?** Ревьюеры Авито уже так делают. Отличие: проверенные цитаты, воспроизводимость (промпты версионируются, температура 0, два прогона), единая рубрика для всех ревьюеров, журнал решений и данные не уходят в личные чаты.

**Почему DeepSeek и как с данными?** Для разработки и демо ключ команды и только публичные примеры работ. Модель за интерфейсом: смена одной переменной окружения ставит локальную модель или модель Авито. ПДн и секреты вырезаются до запроса, `.env` из репозитория не передаётся.

**Где тут агент?** DeepSeek Harness исследует снимок репозитория как субагент: только чтение файлов, без shell и сети. Он собирает места и цитаты, балл ставит наш судья по строгой схеме, цитаты сверяет код.

**Что с ИИ-сигналом?** Не процент, а уровень с основаниями и ограничениями, плюс вопросы для разговора со студентом. В балл не входит. Признаки процесса из git пока недоступны: снимок приходит без истории, это план на пилот.

**Метки корпуса не совпали?** Две работы из корпуса помечены не так, как они устроены: «среднее» Go содержит только часть первого задания, «слабое_1» лабы 1 сильная работа. Ручная разметка по таблице критериев и система здесь согласны, метка нет. Это аргумент за покритериальную оценку, а не за ярлык.

**Код запускаете?** Да, с вечера 6 сентября. Отдельный контейнер-песочница без ключей и без выхода в сеть получает собранный бинарник и миграции, гоняет сценарии, написанные по ТЗ курса, и отдаёт факты: «GET /ping → 200, тело pong: как в ТЗ», «слушает 8080 вместо порта из .env: НЕ по ТЗ», «goose up на чистой базе успешно, повтор успешно». Проба решает строку рубрики: как в ТЗ значит полный балл с высокой уверенностью, НЕ по ТЗ значит ноль или доля, а «сервис не стартовал с нашими переменными» ничего не обнуляет и уходит ревьюеру с логом. На сильном решении корпуса все 16 строк, решённых запуском, совпали с ручной разметкой, на слабом запуск нашёл то, чего по коду не видно: без базы сервис стартует и не паникует. Один прогон песочницы это 6–25 секунд, модель для него не нужна.

**Чего нет?** Тестов курса в песочнице (сценарии написаны по ТЗ, тестов в корпусе нет), истории коммитов, второй независимой разметки, калибровки сигнала на реальном потоке. Изоляция песочницы контейнером, для промышленного контура нужна VM или gVisor. Всё это перечислено в `docs/AI_CORE.md`, раздел «Ограничения».

**Сколько стоит в месяц?** Допущение: поток 100 студентов, 12 заданий, две итерации, по 4 ₽ за работу Go: около 10 тысяч рублей в месяц на модель. Курс 80 ₽ за доллар это допущение из `prereview/pricing.json`.

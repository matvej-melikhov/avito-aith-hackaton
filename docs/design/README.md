## Сборка

`kit.html` и `screens.html` держат стили внутри себя, чтобы открываться где угодно: ссылкой, вложением, перетаскиванием в браузер. Источник правды при этом остаётся в двух CSS-файлах.

После правки `tokens.css` или `components.css` нужно вклеить их заново:

```bash
python3 docs/design/build.py
```

Скрипт подменяет блок между маркерами `<!-- css:start -->` и `<!-- css:end -->`. Руками внутри этого блока ничего не правим, изменения затрутся. В `deck.html` вклеивается ещё и `deck.css`, у слайдов свой слой поверх общих компонентов.

После сборки проверьте связанные состояния:

```bash
python3 docs/design/check.py
```

Проверка не требует сторонних библиотек. Она проверяет общие классы, поля, подписи, режимы просмотра и актуальность встроенных стилей; визуальную проверку в браузере не заменяет.

## Как распространять правки

Правка общего компонента применяется ко всем его состояниям и примеру в `kit.html`, а не только к экрану, на котором заметили проблему.

| Семейство | Где проверять | Что сохраняет различия |
|---|---|---|
| Сдача работы | С1, С2, С3 | Результаты проверок, попытки, остаток запусков ИИ, «Отправить исправления» на С3 |
| Карточка ревью | Р5, Р6 | На Р6 вкладки попыток и данные новой версии; оценки и тексты не копируются из Р5 |
| Разбор требований | Р5, Р6, К9, пример в ките | На К9 баллы только читаются; управление оценкой не появляется |
| Шкала оценки | Р5, Р6, предпросмотр К6, кит | К6 показывает конфигурацию, не редактирует результат студента |
| Меню ревьюера | Р2–Р6 | Выбранный раздел соответствует текущему месту |

К4 (пара дат), история решений К9 и контекст выгрузки К10 пока имеют по одному применению. С4 и С5 показывают список или результат, поэтому форму новой сдачи туда не добавляем. К8 не меняем в рамках согласованного UX-разбора. Исторические варианты оформления и `ux-review.html` остаются снимками прежних решений, их не пересобираем из новых экранов.

Правило: в разметке не должно быть ни одного HEX и ни одного размера мимо `tokens.css`.

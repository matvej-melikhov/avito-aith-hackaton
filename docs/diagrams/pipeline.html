Как проверяется одна работа

Вход: работа студента и замороженная рубрика. Выход: заполненная таблица критериев, где у каждой оценки есть «почему». Ревьюер не ждёт: таблица заполняется по мере готовности.

Подготовка · без модели · секунды

Входссылка на PR или файл, номер итерации, версия рубрики. Одинаковый вход считается один раз
↓
1. Снимок работыклон на нужный коммит с историей или скачанный файл. Дальше работаем только со снимком
↓
2. Метаданныекоммиты, время, авторы, размеры; для docx автор и история правок; опоздание к дедлайну → штраф
↓
3. Карта работыфайлы с номерами строк; для Go разбор кода: пакеты, функции, интерфейсы, теги, импорты, кто кого вызывает. Чтобы любая цитата имела адрес
↓
4. Анонимизация и защитаФИО, почты, ключи → плейсхолдеры. Инструкции для модели внутри комментариев вырезаются из срезов и ставят флаг. Только после этого что-то уходит в модель
↓дальше четыре класса строк рубрики идут параллельно

Проверки · параллельно

A. Тестыпесочница без сети, тесты курса снаружи кода студента: сборка, миграции на чистую базу, /ping, флаг --port, SIGTERMфакт · принять кликом
B. Статикадюжина примитивов: файл есть, grep, импорт, AST-запрос, счётчик. «есть go.mod», «нет fmt.Print», «интерфейсы приватные»факт · принять кликом
C. Модель с цитатой
выбор файлов по карте: «нет логики в handlers» → только internal/handler, до 6 файлов
один вызов на строку: рубрика строки + заметки + ТЗ + факты из A и B + срезы кода
ответ по схеме: вердикт, балл или диапазон, уверенность, цитаты файл:строки, «чего нет и где искали»
программа ищет каждую цитату в коде. Не нашла → цитата снимается, уверенность падает, флаг
второй прогон. Разошлись → берём осторожный, уверенность низкая, показываем оба
предложение · ревьюер подтверждает
D. Наблюдениядля оценочных строк: 2–3 факта с цитатами, без балла. «функция handleAssign 140 строк»решает человек
ИИ-сигналgit-процесс, стиль против прошлых заданий студента, промахи по ТЗ, артефакты, декларация → уровень, основания, вопросы для Q&Aвне баллов
↓

Сборка · без модели

5. Таблица и итогзначение «Авто» на строку → веса → суммы групп → флаг на критичное → штраф отдельной строкой → итог как в шаблоне, максимум по итерациям. Две цифры: предложено и подтверждено
↓
6. Очередьпервыми к ревьюеру: критичное провалено, ИИ-сигнал, неподтверждённые цитаты, разброс повторов, балл у порога, вторая итерация
↓
7. Черновикиодин вызов без кода: комментарий студенту на каждую группу, 2–4 пункта, и три пункта ревьюеру «на что смотреть первым»
↓
8. Записьнеизменяемая: версии рубрики, пайплайна, промптов, модель, токены, все логи. По любой ячейке можно открыть «как это получилось»
↓
9. Ревьюервидит таблицу с «Авто» и «Почему», принимает всё с высокой уверенностью одним кликом, ставит оценочные сам, правит черновик, утверждает
↓
Решения ревьюеракаждая строка хранится парой «предложено → решено»
↺ Из пар по всему пулу выводятся интерпретации критериев. Непроверенные работы пересчитываются, подтверждённые не трогаются. Строки, где модель нестабильна на многих работах, уходят методисту как «нечёткая формулировка». Это возвращается в шаг C на следующем прогоне.

Вторая итерация

Досдачадифф между коммитами → перепроверяются только строки не на максимуме и строки, чьи файлы изменились. Остальное «без изменений». Ревьюер видит, какие замечания закрыты. Вопросы ИИ-сигнала подставляются в колонку «после Q&A»

Если что-то упало

Сборка не прошла. Строки A «не проверено, сборка не прошла». B и C работают дальше: архитектуру видно и по несобирающемуся коду.
Модель недоступна. A, B и сигнал по метаданным отдаются сразу, C «не проверено», повтор по расписанию.
Файл недоступен. Единственная полная остановка: работа поднимается ревьюеру и методисту.
Правило. Никакая ошибка не превращается в провал строки. Провал только по факту.
Одной фразой. Половина таблицы заполняется программой без модели. Модель отвечает на маленькие вопросы по одной строке и только цитатами, которые программа проверяет. Всё, что не подтвердилось, не прячется, а показывается ревьюеру флагом. Порядок величины: единицы рублей и до пяти минут на работу.

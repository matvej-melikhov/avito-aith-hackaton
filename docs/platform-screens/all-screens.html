Что меняется

Раньше координатор публиковал условие где-то ещё, а система пыталась распознать критерии из него. Каждую работу раскладывал по ревьюерам, узнавая заранее, кто сколько готов взять.

Было

  1. Условие пишется в GitHub, Stepik или PDF
  2. Система пытается распознать критерии оттуда
  3. Координатор вычитывает и правит распознанное
  4. Координатор узнаёт у каждого ревьюера ёмкость
  5. Координатор раскладывает работы по ревьюерам

Стало

  1. Координатор один раз описывает задание в форме на платформе
  2. Сохранил — задание сразу видно ревьюерам
  3. Ревьюер сам указывает, сколько готов взять
  4. Система отдаёт ему работы из пула под эту ёмкость
  5. Координатор возвращается, только если что-то застряло

Пять шагов вместо пяти — но три из них теперь делает не координатор.

Главное действие

Понять, чего не хватает, и вернуться к работе. Проверка идёт против требований из условия, а не против наших формулировок.

Чего на экране нет, и это принципиально
  • баллов и предварительной оценки, иначе экран превращается в торг,
  • блока с признаками использования ИИ: увидев его, студент просто уберёт признаки, а решение об этом принимает ревьюер,
  • безлимитных попыток, иначе это перебор вариантов, а не самопроверка.

Почему без автоматического разбора

Мы рассматривали вариант «система сама вытаскивает критерии из готового условия» — на системном дизайне это было бы почти бесплатно, рубрика там уже лежит таблицей. Отказались: ошибка распознавания тихо портит оценку всем студентам потока, а вычитывать чужой черновик выходит не быстрее, чем сразу написать свой. Форма — тот единственный раз, когда координатор садится за задание.

Критерии можно менять и после публикации

По интервью критерии иногда правят прямо в середине потока, если ошибку заметили рано. Правки сохраняются новой версией, а не поверх старой — уже прошедшие проверки остаются воспроизводимыми на своей версии.

Кнопки «назначить принудительно» нет намеренно, кроме одного случая

Пока есть время до срока, координатор только шлёт напоминания — принудительного назначения нет, чтобы не тихо вернуться к push. Но по интервью на реальном курсе за день до отчёта студентам методист сам разбирает хвосты, если никто из ревьюеров не подхватил. Это не общий выход из pull, а разовый рычаг с жёсткой границей по времени — открывается только после срока сдачи, до этого момента его не видно вообще.

Часть экранов оставлена только текстом в реестре, без макета: вход для ревьюера и координатора, общий профиль пользователя, архив прошлых потоков. Это стандартные паттерны — форма логина и общие настройки выглядят одинаково в любом продукте, макет здесь не добавляет информации, только объём. Управление составом ревьюеров, отдельная статистика и эскалации по потоку туда же — по функции они не отличаются от уже нарисованных таблиц и карточек, дублировать вид ради нового номера экрана не стали.

# Program scope первой реализации

**Актуально на:** 4 сентября 2026 года

Этот документ задаёт авторитетную границу первой реализации. При расхождении с ранними MVP-документами приоритет имеют этот файл и спецификации `specs/001`–`specs/004`.

## Обязательный вертикальный сценарий

1. Оператор self-hosted установки назначает первого методиста.
2. Методист входит, импортирует тестовый курс и студентов через Stepik mock и создаёт домашнее задание с критериями.
3. Студент входит через Stepik mock и отправляет GitHub или Google Docs ссылку.
4. Ревьюер входит по приглашению на email и одноразовому magic link; Stepik ему не требуется.
5. Backend проверяет доступ, сохраняет версию артефакта и запускает AI-review через согласованный внешний контракт.
6. Ревьюер выбирает курс, указывает планируемые часы и получает рекомендованную работу.
7. AI-черновик появляется по мере готовности; его отказ не блокирует человека.
8. Ревьюер или методист публикует человеческий отзыв и балл.
9. Для GitHub результат доставляется в доступную GitHub-цель. Для Google Docs полный отзыв остаётся в платформе.
10. Stepik mock принимает балл и текстовый feedback; backend показывает состояние доставки и ошибки.
11. Студент отправляет доработку, после чего ревьюер или методист открывает следующую итерацию ревью.

## Реализуется сейчас

- backend core для одной self-hosted организации с архитектурной tenant-границей;
- роли методиста, ревьюера и студента;
- Course Run, домашние задания и версионируемые критерии;
- сдачи, повторные версии и итерации ревью;
- pull-рекомендация работ и мягкий план часов;
- интеграционный контракт внешнего AI-review;
- GitHub adapter для поддерживаемых URL и ограниченного снимка;
- Google Docs adapter для одновкладочного DOCX до 10 MB;
- внешние доставки, повторы, reconciliation, аудит и телеметрия;
- REST API и MCP `2026-07-28` со stateless HTTP core над теми же правами;
- Stepik mock/replay для курса, студентов, OAuth и доставки оценки.

## Отдельные внешние gates

- live Stepik roster и grade passback через `manual-score`;
- GitHub App installation и публикация в приватный fixture;
- email sender или локальный mailbox fixture для magic link ревьюера;
- согласованный и версионированный AI request/result/event contract.

## Позже

- multi-tenant SaaS runtime и control plane;
- курсы без Stepik и альтернативная регистрация студентов;
- LTI и live Stepik integration без подтверждённого `manual-score`;
- Git LFS, submodules, GitHub Enterprise и inline review comments;
- многовкладочные Google Docs и публикация комментариев в Google;
- реализация AI-моделей, промптов, проверок и evals в backend-репозитории;
- необратимое удаление курсов и данных через продуктовый интерфейс.

## Порядок реализации

1. Общие contract schemas и contract tests.
2. Каркас backend, миграции и локальное окружение.
3. Организация, роли, Course Run, задания и сдачи.
4. Артефактный контракт и адаптеры GitHub и Google Docs.
5. AI-review orchestration с mock AI-компонентом.
6. Итерации человеческого ревью и pull-рекомендация.
7. Outbox, доставки, Stepik mock и reconciliation.
8. REST и MCP acceptance tests.
9. Live integration gates, если доступны нужные внешние права.

## Definition of Done

- все обязательные пользовательские сценарии `specs/001`–`specs/004` имеют исполнимые acceptance tests;
- backend и AI mock проходят общий набор contract fixtures;
- одна GitHub и одна Google Docs сдача проходят сквозной сценарий;
- повторная версия создаёт отдельную итерацию ревью и сохраняет историю;
- отказ AI и каждого внешнего провайдера виден и не уничтожает человеческий результат;
- cross-tenant tests не допускают чтение, запись или фоновое действие в чужой организации;
- незакрытые live gates перечислены явно и не выдаются за реализованное поведение.

# Оценка учебных работ

**Дата:** 6 сентября 2026. **Модель:** `deepseek-v4-flash`.

Корпус: [homework_examples](https://github.com/ai-talent-hub-avito/homework_examples/tree/7a72e08ab417f3ff6503467b51f5a58157fa833a), коммит `7a72e08`.

## Как проверяли

60 работ по 22 заданиям проверены через backend → reviewer-assist → prereview. Получено 66 ревью: каждый из трёх Go-репозиториев оценён отдельно по заданиям 1–3. Имена с метками качества скрыты от оценщика.

DOCX, PDF и Markdown переданы исходными файлами. Репозитории переданы ZIP-архивами; для Go выполнены `go build` и `go vet`. XLSX, HTML и notebooks преобразованы в Markdown с формулами, значениями ячеек, кодом и текстовыми результатами. Пропуски визуальных данных отмечены в подготовленных артефактах.

## Правила расчёта

- Хорошие работы относятся к нормальным. Средние оцениваются, но не входят в метрики классификации.
- Для работ с меткой «слабая», получивших зачёт ИИ, проведена отдельная проверка по условию и рубрике: достигшие порога относятся к нормальным, остальные — к слабым.
- Порог зачёта — 60% максимума. Для System Design №1 — 4/6, для №2 — 6/10; обязательные минимумы по критериям также учитываются.
- Критерий без предложенного балла получает максимальный балл при расчёте итога. Исходный ответ ИИ сохраняется.
- Положительный класс — **слабая работа**, положительный прогноз — **незачёт**.

Что изменила песочница по существу: в задании 2, где проверяются база, миграции и CRUD, слабое решение потеряло полбалла, а хорошее прибавило балл. В построчной калибровке (`docs/CALIBRATION.md`) те же строки у слабого решения давали от 7 до 8.5 балла, а ручная разметка по рубрике даёт 8.5.

Единственное изменение это пара go_3 слабого решения. По правилу этого отчёта слабая работа, получившая зачёт ИИ, проходит отдельную проверку по рубрике, и достигшая порога относится к нормальным. Ручная построчная разметка (`prereview/evals/labels/go_tasks_1_3.json`) даёт этой работе по заданию 3 те же 8.5 из 14, порог 8.4, то есть по правилу отчёта пара переходит в нормальные. С учётом этого: совпадение 39/44 — 88,64%, precision 10/11 — 90,91%, recall 10/14 — 71,43%, F1 80,00%. Разница между двумя вариантами это одна пограничная работа, а не эффект песочницы. Вывод: на уровне «зачёт или незачёт» песочница метрики не меняет, её эффект виден в построчных метриках (`docs/CALIBRATION.md`: 34 из 36 строк, решённых запуском, совпали с разметкой).

## Ранжирование: сохраняется ли порядок «слабая, средняя, хорошая»

Скрипт `ranking.py` (результаты в [ranking.json](ranking.json) и [ranking-sandbox.json](ranking-sandbox.json)). Внутри одного задания сравниваются все пары работ с разными референсными классами: пара согласована, если работа с более высоким классом получила больший балл, ничья считается за половину. Для двух классов эта доля равна AUC. Средние работы здесь участвуют.

| Метрика | Значение |
|---|---:|
| Пар внутри заданий | 60 (22 задания) |
| Согласовано / рассогласовано / ничьих | 37 / 8 / 15 |
| Pairwise accuracy, все пары | 74,2% |
| Слабая против хорошей | 16 пар: 13 согласовано, 0 рассогласовано, 3 ничьих — 90,6% |
| Слабая против средней | 15 пар — 70,0% |
| Средняя против хорошей | 29 пар — 67,2% |
| AUC слабая против нормальной, доля от максимума по всем заданиям | 0,916 (435 пар) |
| Заданий с полностью верным порядком | 7 из 22 |

Что стоит за числами. Слабую работу от хорошей система не путает ни разу: все 8 рассогласованных пар это «средняя» против соседнего класса. Две из них это Go 2 и Go 3, где среднее решение корпуса содержит только часть задания 1 и по существу слабее слабого (см. `docs/CALIBRATION.md`). Остальные шесть и 10 из 15 ничьих приходятся на продуктовые и аналитические задания без файла настроек, где система ставит максимум и средней, и хорошей работе: рубрики там короткие, подсказок к критериям нет. На заданиях с файлом настроек (Go 1–3, системный дизайн 1) pairwise accuracy 76,9% по 13 парам, и оба рассогласования это упомянутая метка среднего Go. После перепрогона Go с песочницей ранжирование не изменилось.

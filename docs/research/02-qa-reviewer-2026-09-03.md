# Интервью 02 — ревьюер Tech QA, 3 сентября 2026

Источник: `sources/04-review-meeting-transcript.txt`. Участники: ревьюер курса тестирования API, команда продукта.

## Процесс проверки

- **Т1. Калибровка = создание критериев + golden set.** Собираются всей командой ревью, пишут эталонное решение на Go, на его основе формулируют жёсткие критерии приёмки.
  - *Цитата:* «собираемся и все вместе составляем критерий приёмки ... сами выполняем работу ... golden set»
  - *Implication:* в форме создания задания нужно поле `эталонное решение`, не только список критериев `docs/08-review-core.md`.
- **Т2. Ручной baseline — час на работу.** Первые два потока проверяли без модели.
  - *Цитата:* «примерно час уходил на проверку работы одного студента»
  - *Implication:* база для замера эффекта, заменяет допущение `15–30 мин`.
- **Т3. С моделью — 10–15 мин, 4–6× быстрее.** Весной внедрили навык (skill) с критериями + примерами, с осени 2025 шёл прогон через модель.
  - *Цитата:* «минут 10–15 занимает проверка одной работы»
  - *Implication:* целевой ориентир для нашего MVP.
- **Т4. Выход модели — структурированный отчёт по критериям с баллами + черновик комментариев в код.**
  - *Implication:* карточка ревьюера должна показывать вердикты и черновик фидбека раздельно.

## Роль человека

- **Т5. Человек валидирует всё.** Даже при 90% согласия ревьюер вычитывает, перепроверяет выборочно, правит.
  - *Implication:* подтверждает контракт К1, журнал `предложение → правка → финал`.
- **Т6. Деление труда уже существует.** Модель — формальная часть (сопоставление, счёт, поиск ошибок в коде), человек — понятность/удобство кода на год вперёд не отдадут модели.
  - *Цитата:* «мы всё-таки растим инженеров ... пока будем смотреть глазами»
  - *Implication:* подтверждает три класса требований.

## Сигнал об ИИ

- **Т7. Не запрет, а вычет за «не пропустил через себя».** Порог >80% на фронтир-модели (Claude/GPT-5), открытые дают плохо.
  - *Implication:* сигнал с уверенностью + основания, решает человек, `docs/04-contracts.md:К2`.
- **Т8. Критерии специально неполные, чтобы не скормить модели.** Проверено: отдал хорошо структурированное условие модели, сдал как студент — прошло.
  - *Implication:* риск для саморевью, `docs/03-platform.md:риск`.

## Координация

- **Т9. Дедлайн жёсткий: 2 дня от закрытия приёма до отчёта студентам** (пн 16:00 → ср), 100 студентов, 5–6 ревьюеров, до 20 работ/чел, сдаёт 80%.
  - *Implication:* параметр потока, не константа 7 дней.
- **Т10. Распределение — равное деление + неформальный pull при форс-мажоре.** «Не успеваю — подхватите».
  - *Implication:* наш pull — предложение, в реальности гибрид.

## Итерации

- **Т11. Доработка не влияет на балл** (кроме окна до дедлайна), но помогает учиться. Пересчёт баллов после отправки — редко, только по ошибке критериев.
  - *Implication:* экран сравнения версий.

# Usability: after-c1-final

Outcome: COMPLETED. Самостоятельно через UI созданы поток и опубликованное задание; сохранение проверено перезагрузкой и повторным просмотром всех трёх шагов. Исходники, API, БД, память и чужие отчёты не использовались. Другие курсы не открывал и не изменял.

## Цели и доказательства

- Курс: «Практикум · учебная программа». Создан поток «Практикум · учебная программа · 2026-10-01». Карточка после возвращения показывает 1 окт. 2026 г., 00:00 — 15 нояб. 2026 г., 23:59.
- Задание: «Контракты HTTP». Условие после reload: «Опишите HTTP API: методы, пути, параметры запросов и форматы ответов. Опишите обработку ошибок: коды HTTP, структуру сообщения об ошибке и примеры неуспешных запросов.»
- Два критерия: «Описание HTTP API» — 5; «Обработка ошибок» — 5. После reload оба названия, тексты выполнения и баллы восстановились. Порог 6 из 10.
- Лимит самопроверок 2 после reload.
- Сдача: 15.10.2026 23:59; проверить до: 20.10.2026 23:59. Оба значения сохранены после reload на шаге публикации.
- Формат «Ссылка или файлы» подтверждён активной кнопкой на screenshot и текстом таблицы заданий потока.
- Публикация выполнена. После reload показаны дата публикации, срок, ссылка для Stepik: http://127.0.0.1:5180/#/prepare/01a07358-3466-7cf6-b182-0fef226a88f3 . В потоке появилась строка задания с 10 баллами и сроком 15 октября.
- Студентов и ревьюеров в новом потоке 0; их добавление не входило в сценарий. Доступность ссылки подтверждена в интерфейсе, вход по ней от лица студента не проверялся.

## Маршрут

Обзор → Создать поток → выбор курса и даты → новый поток в таблице → Название / Создать задание → Для студента (условие, формат, сдача, 2 самопроверки) → Критерии ревью (два критерия, по 5, порог 6) → Публикация (проверить до 20 октября) → Опубликовать задание → reload → проверка трёх шагов → Задания потока. До 45 UI-действий, без тупиков и подсказок о кнопках.

## Боли

1. Экран «Создать поток» из общего обзора, поле «Курс». Ожидание: явный выбор курса. Факт: изначально выбран первый чужой курс «Практикум · команда и нагрузка», хотя есть опция «Выберите курс». Влияние: при невнимательном вводе дат можно создать поток в чужом курсе. Минимальная идея: из общего обзора оставлять пустой выбор; предзаполнять только при входе из конкретного курса.
2. Экран публикации, «Опубликовать в потоке». Ожидание: перед финальным действием увидеть название целевого потока и итог требований. Факт: показаны версия, лимит и сроки, название потока отсутствует; breadcrumb говорит только «Задания потока». Влияние: приходится полагаться на свой маршрут, чтобы убедиться, что публикуешь куда нужно. Минимальная идея: вывести название потока и краткую сводку 2 критерия / 10 баллов / порог 6 / формат сдачи.
3. После успешной публикации остаётся активная кнопка «Опубликовать задание». Ожидание: явное состояние завершения. Факт: успех понятен по появившейся ссылке, но основное действие выглядит незавершённым. Влияние: возникает сомнение, нужно ли нажать ещё раз. Минимальная идея: статус «Опубликовано» и отдельное действие изменения публикации.
4. Русская форма дат на screenshot использует 10/15/2026, 11:59 PM, а file input — Choose Files / No file chosen. Ожидание: привычные локализованные даты и действия. Факт: native controls на английском. Влияние: при дне <=12 легче перепутать месяц и день. Минимальная идея: обеспечить русскую локаль или рядом выводить однозначную дату словами.

## Инструментальные наблюдения

Сбоев инструмента не было. Некоторые ответы сразу после перехода показывали только часть уже загружаемого экрана или не все controls; следующий snapshot показывал полный экран. Повторных кликов по отправке не делал. Это не считаю доказанным UX-дефектом: моментальный инструментальный снимок мог попасть в загрузку.

# Usability: первая проверка «Пагинация списка задач»

outcome: COMPLETED

Роль: Елена Смирнова, ревьюер. actor=after-r1-final. Только видимый интерфейс; исходники, API, БД и чужие отчёты не использовались. Другие работы не открывал и не менял. Инструментальных сбоев не было.

## Цели и доказательства

- Нашёл нужную первую сдачу в «Пул»: «Пагинация списка задач», курс «Практикум API · проверка работ», попытка 1.
- Открыл new-api.md в отдельной вкладке. В материале описаны GET /tasks, POST /tasks, пустой заголовок → 400 и три общих шага проверки. Точных запросов и JSON-ответов нет.
- Прочитал условие: реализовать HTTP API списка задач, описать основные сценарии и проверки ошибочных запросов в README. Критерии по 5 баллов, порог зачёта 7/10.
- Запросил AI-разбор. Получил честно помеченную демонстрационную рекомендацию «Реальная модель не вызывалась», по 2.5/5 и демо-отзыв. Принял собственное решение: 3/5 за основной сценарий и 1/5 за ошибки, итог 4/10. Заменил оба обоснования и отзыв.
- Отзыв содержит команду запуска/адрес API, готовые HTTP или curl-примеры, ожидаемые статусы и JSON; негативные случаи пустого заголовка, отсутствующего title и некорректного JSON, проверку отсутствия ошибочно созданной задачи, исходные данные и шаги повторения.
- Сохранил черновик, вернул на доработку, задал 08.09.2026 18:00 и краткий список исправлений, подтвердил публикацию.
- Финальный экран: «Нужны правки», «Ревью опубликовано студенту», «Исправления до 8 сент. 2026 г., 18:00», итог 4/10, мои обоснования и полный отзыв. Это подтверждение со стороны интерфейса ревьюера; в аккаунт студента не входил.
- Вернулся в «Мои работы»: целевая строка «Нужны правки», «Проверить до 8 сент.», действие «Посмотреть».

Мои работы → Пул → Начать проверку у нужной строки → Открыть new-api.md → вкладка материала → обратно → Получить AI-разбор → собственные баллы, обоснования, отзыв → Сохранить черновик → Вернуть на доработку → срок и исправления → Подтвердить публикацию → Мои работы.

На домашнем экране целевой работы не было; логично пошёл в пул и сразу нашёл её по названию и курсу. При первом снимке карточки файл был только текстом, без «Открыть»; следующий снимок уже показал ссылку. Неудачных кликов и повторов без прогресса не было. После изменения AI-балла появилось поле собственного обоснования, поэтому продолжил вручную без поиска другой команды.

## Боли

1. Экран карточки, название «Пагинация списка задач», но условие и материал — общий API без требований к пагинации. Ожидал параметры/границы страниц. Фактически опирался только на показанные два критерия и не придумывал штраф за отсутствующую пагинацию. Влияние: непонятна полнота задания. Минимальная идея: согласовать заголовок с условием либо добавить конкретные требования пагинации.
2. «Получить AI-разбор по критериям» заменил пустой отзыв и оценки демо-значениями. Ожидал полезный разбор материала, получил служебное «Локальный fixture» и просьбу проверить самому. Влияние: помощь не помогла анализу, пришлось переписать всё. Минимальная идея: предупреждать о деморежиме до запуска и не считать демонстрационный текст готовым обоснованием.
3. После AI-разбора поля обоснования исчезли и появились снова при изменении баллов. Ожидал постоянно доступный способ написать своё объяснение независимо от согласия с баллом. Фактически нашёл его побочным действием при коррекции оценки. Влияние: если балл устраивает, путь исправления объяснения неочевиден. Минимальная идея: явное «Изменить обоснование» у каждого критерия.
4. Галочка у обоих критериев сохраняется даже при 1/5 и решении «Нужны правки». Ожидал, что галочка означает выполнение. Фактически она, вероятно, обозначает наличие разбора, но это не объяснено. Влияние: визуально низкая оценка выглядит положительной. Минимальная идея: заменить на нейтральный индикатор «Оценено» либо отображать выполнение отдельно.
5. В окне возврата пустое «Что нужно исправить» после уже заполненного подробного отзыва. Ожидал переиспользование текста либо объяснение назначения второго поля. Фактически снова кратко переписал требования. Влияние: дублирование и риск расхождения. Минимальная идея: подпись «Краткий список исправлений, будет показан отдельно от отзыва» или автоподстановка.
6. Итоговая панель на первом full-page снимке пересекала левую колонку ответа студенту. Ожидал беспрепятственно видеть заголовок и поле отзыва. Фактически часть колонки закрыта фиксированным блоком, затем при прокрутке поле стало доступно. Влияние: лишняя прокрутка и потеря контекста. Минимальная идея: предусмотреть пространство под фиксированную панель.
7. После публикации подпись «Студент получит его вместе с решением» осталась в будущем времени, хотя ниже уже подтверждена публикация. Влияние невелико, но статус чтения двусмысленен. Минимальная идея: «Опубликованный ответ студенту».

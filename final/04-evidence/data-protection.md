# Защита данных и ответственность: меры в MVP и требования к пилоту

7 сентября 2026. Проект Avito AI Reviewer, команда «Крутые Перцы». Код: https://github.com/matvej-melikhov/avito-aith-hackaton, ветка `ai-core`. Числа из `docs/NUMBERS.md` в репозитории.

## Что защищаем и от кого

Кейс ставит два жёстких правила: персональные данные не покидают контур, а вывод модели не становится оценкой без человека. Мы разделили данные на классы и для каждого решили, куда он уходит.

| Класс данных | Куда уходит | Что видит модель | Что видит студент |
|---|---|---|---|
| Работа студента: код, текст | в сервис проверки по подписанной ссылке, бинарник в песочницу | текст после маскирования, без `.env`, без строк-инструкций | свою работу и самопроверку без баллов и цитат |
| ПДн студента: ФИО, почта, телефон | в сервис не передаются, только идентификаторы | почты и телефоны внутри текста заменены плейсхолдерами | свои данные |
| Секреты в репозитории: `.env`, ключи | `.env` не читается, ключи заменяются на `<SECRET>` | плейсхолдеры и флаг | флаг видит ревьюер |
| Критерии, указания ревьюерам, эталон | в промпт судьи | целиком | текст задания, порог и максимум |
| Решения ревьюеров, сигнал об ИИ, журналы | в модель не уходят | ничего | опубликованное ревью, сигнал не видит |

Угрозы, на которые есть мера в коде: ПДн в промпте и логах, секреты студента, обучение провайдера на данных, инъекция инструкций в работе, вредоносный код в песочнице, подмена снимка работы, доступ агента через MCP без разрешения, ошибка модели или выдуманная цитата, ставшие оценкой.

## Что делает код до вызова модели

1. Снимок скачивается по подписанной ссылке на 15 минут (контракт `specs/005-workspace-completion/ai-handoff.md`) с проверкой sha256 и размера. Несовпадение даёт отказ, а не проверку чужой работы.
2. Файлы `.env` из снимка не читаются. Почты, телефоны, ключи и токены заменяются плейсхолдерами (`prereview/src/prereview/artifact/redact.py`).
3. Строки, похожие на инструкции модели («поставь максимум», «ignore previous»), вырезаются с сохранением номеров строк. Ревьюер видит флаг у каждого критерия и в сигнале об ИИ.
4. Промпт судьи подаёт работу как данные, не как инструкции. Промпты лежат файлами в `prompts/`, 8 файлов, версия равна хешу содержимого.
5. Запрос от платформы не содержит ФИО, почты и телефона. Аудит платформы удаляет токены, ссылки с секретами и почты до записи. Ссылка-приглашение хранится хешем и работает один раз.

## Что ответ модели не может сделать

Ошибка модели никогда не превращается в оценку. Цепочка одна для всех критериев:

- ответ принимается только по строгой схеме, при отказе повтор с текстом ошибки, затем статус «не проверено» и заметка «проверьте вручную»,
- балл выше нуля показывается только с цитатой, которую код нашёл в работе. Не нашёл, значит вердикт уходит ревьюеру без балла,
- два прогона при температуре 0. Разошлись, значит берётся осторожный вердикт с низкой уверенностью и оба обоснования ревьюеру,
- отказ исследователя репозитория (Harness) даёт фолбэк на усаженный текст, отказ песочницы даёт строки ревьюеру с пометкой, не ноль,
- итоговый балл подтверждает ревьюер. Автоматической записи оценки нет.

Замеры 6 сентября, DeepSeek v4 flash, температура 0:

| Показатель | Лаба 1 системного дизайна | Go, задания 1–3 |
|---|---|---|
| Баллов выше нуля с подтверждённой кодом цитатой | 34 из 34 | 74 из 74 |
| Цитат модели отклонено верификацией | 6 | 1 |
| Расхождение двух повторов | 0 % строк | 3 % строк |
| Строк «нужен ревьюер» | 7 % | 1 % |
| Инъекция «поставь максимальный балл» в тексте работы | сумма 5.5 → 5, сигнал об ИИ low → medium, строка вырезана | не проверялась |

На всём публичном корпусе (60 работ, 22 задания) завершились 66 из 66 прогонов, у каждого записаны токены и стоимость.

## Песочница запуска

Код студента на Go исполняется только в отдельном контейнере `runner`. Свойства проверены на podman 6 сентября: внутренняя сеть без выхода наружу и без внешнего DNS, в образе нет ключей и кода сервиса, корень только для чтения, рабочий каталог в tmpfs, все capabilities сняты, лимиты памяти, процессов и CPU, таймауты на старт, пробы и остановку. На каждый сценарий создаётся своя роль и база в тестовом Postgres, после сценария всё удаляется. Запуск закрывает 16 из 40 строк рубрики Go, совпадение с ручной разметкой 34 из 36.

Ограничение: изоляция контейнерная, не VM. Для промышленного контура нужен gVisor или отдельная виртуальная машина.

## Провайдер модели: хакатон и пилот

Условие кейсодателя: провайдер либо внешний с договором без обучения на данных, либо локальная модель в контуре, внешние агенты запрещены.

| | Хакатон | Пилот |
|---|---|---|
| Модель | DeepSeek v4 flash по ключу команды | локальная модель через OpenAI-совместимый API или провайдер с договором без обучения на данных |
| Данные | только публичный корпус примеров | реальные работы |
| Как переключить | переменные `PREREVIEW_LLM_PROVIDER`, `PREREVIEW_LLM_MODEL`, `PREREVIEW_LLM_BASE_URL` | те же переменные, код не меняется |
| Что перепроверить | | перепрогон evals на том же корпусе и разметке, сравнение с цифрами выше до допуска к реальным работам |

Harness работает локальным процессом внутри контейнера сервиса в режиме только чтения: без shell, сети, записи и субагентов. Это не внешний агент.

## Что не сделано и ворота пилота

| Требование | Статус | Ворота |
|---|---|---|
| Модель внутри контура Авито | план | 0 запросов к внешнему провайдеру, проверка по конфигу и сетевой политике |
| Песочница на gVisor или VM | план | тест изоляции проходит в CI |
| ФИО внутри текста работы | не маскируются | поиск ФИО из базы по тексту перед отправкой |
| Сканы PDF | картинки уходят в vision-модель до маскирования | вне контура выключить распознавание |
| Проверка выхода модели на ПДн | нет | те же шаблоны на текст обоснований |
| Срок хранения снимков в сервисе | не удаляются | задача очистки по сроку, как в платформе |
| Ротация ключа провайдера и токенов сервиса | статичны в `.env` | секреты из хранилища, ротация по регламенту |
| Шифрование полей для работ и ПДн | нет | шифрование диска и бакета в контуре |
| Аудит скачивания работы ревьюером | не найден в коде | добавить событие аудита |
| Согласие студентов на автоматическую проверку и сигнал об ИИ | нет | уведомление и согласие до первого потока |
| Процедура апелляции | нет | второй ревьюер или координатор |

## Ответственность

Финальное решение принимает человек, и это держит код: без подтверждения ревьюера балл не записывается. Каждый вердикт с цитатой, каждая правка в журнале: предложение системы, правка человека, финал. Сигнал об ИИ не меняет балл и не запускает санкции, студент его не видит. Два пункта остаются за Авито Образованием: уведомление студентов о проверке и канал апелляции. Без них пилот на реальных работах начинать нельзя.

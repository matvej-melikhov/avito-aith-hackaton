# Фронтенд платформы ревью

Настройка «Что прикрепляет студент для ответа» использует поле `allowed_sources` API v2 из актуального `backend` (проверено с `5b4ae15`). В `design-site` синхронизированы соответствующие поля OpenAPI и типы клиента; серверный код этой ветки в рамках изменения не обновлялся. Для работы этой настройки запускайте фронтенд с API ветки `backend`, как в текущем локальном стенде.

Пункты «Ссылки» и «Файлы» независимы: можно разрешить один или оба типа, пустой набор сохранить нельзя. Выбор сохраняется в черновике и версии задания; студент видит только разрешённые варианты. Разрешение обоих типов означает выбор способа ответа, а не прикрепление ссылки и файла одновременно в одной попытке.

Локальное React/TypeScript-приложение. Экраны собраны один в один по дизайн-паку `../docs/design/screens.html` (22 экрана) на классах `../docs/design/components.css` и токенах `../docs/design/tokens.css`; содержание экранов и логика статусов — из `../docs/platform-screens/`. Работает с REST-контрактом `../specs/001-backend-core/contracts/openapi.yaml` и командным контрактом `command.schema.json`.

## Дизайн-система в коде

| Где | Что |
|---|---|
| `src/styles.css` | подключает `tokens.css`, `components.css` и `src/ds/ds.css`; дальше только сброс нативных контролов и высота на весь экран |
| `src/ds/ds.css` | модификаторы, снятые с инлайновых `style=""` эталона, каждый с ссылкой на строку `screens.html`; правила для живого приложения (модалка в `<dialog>`, тосты, узкое окно) |
| `src/ds/*.tsx` | тонкие React-обёртки над классами пака: `Shell/Topbar/Main/Band/Crumbs/Steps`, `Btn/Pill/St/Seg/Tabs/Chk/Tgl/Field/Inp`, `Card/Kv/Tiles/Callout/Empty/Skel/Meter`, `Acc/Ck/Scale/Finding/Code/Quote/Crit`, `Modal/Toast/Srch/Pop` |
| `src/ds/status.ts` | карта статусов API на семь статусов домашки (`workStatus`) и тон служебных пилюль (`opTone`) |
| `src/ds/format.ts` | даты и числа в формате эталона: «17 фев», «18 февраля, 21:40», «18.02, 21:40», «4,5 из 6» |

Правила: в разметке нет HEX и px мимо токенов, `tokens.css` и `components.css` не редактируются (после их правки пак пересобирается `python3 docs/design/build.py`). Каждая страница помечена `data-screen` с кодом экрана из `screens.html`, по нему удобно сверять вёрстку с эталоном.


## Удобство сверх эталона

- Шапка экрана и панель разделов липкие: заголовок, крошки и действия остаются на месте при прокрутке.
- На длинных экранах (карточка работы, мастер задания) внизу липкая панель действий: итог и решение всегда под рукой.
- Плотность подобрана под ноутбук 1440×900: рабочие списки, кабинеты и страница сдачи помещаются без прокрутки.
- Кабинеты у всех трёх ролей: студент (`#/cabinet`: сводка домашек, курсы, учётная запись), ревьюер (`#/preferences`, `#/statistics`), организатор (`#/cabinet`: профиль и потоки, участники, доставки).
- Ревьюер открывает работу из пула явной кнопкой. После публикации остаётся на результате; следующая работа открывается только по нажатию «Следующая работа». «Снять с себя проверку» снимает только участие текущего ревьюера, возвращает в список и показывает сообщение. Разбор модели подставляется сам; черновик сохраняется автоматически.
- Студент открывает задание, историю и форму ответа на одной странице с существующей компоновкой. Старые ссылки `#/submissions/:id` для студента открывают тот же экран; параметр `attempt` раскрывает выбранную попытку. Отправленные попытки доступны только для чтения. Для координатора и ревьюера сохранён отдельный просмотр результата.
- На локальном учебном стенде «Войти через Stepik» открывает объяснение о ненастроенном входе; вместо обращения к OAuth можно выбрать участника. Вне локального стенда сохраняется обычная ссылка начала авторизации.
- Строки таблиц кликабельны целиком, плитки обзора ведут в списки, из которых посчитаны; выбранная роль переживает перезагрузку вкладки.


## Комментарии к интерфейсу

Вверху по центру любой страницы кнопка с карандашом «Комментарий». Она включает режим комментирования поверх интерфейса: наведение подсвечивает блок или текст, клик открывает окно, где пишется, что поменять (Cmd/Ctrl+Enter сохраняет, Esc выходит). На элементе остаётся нумерованная метка, комментарии хранятся в браузере (`localStorage`, ключ `ui-comments`) и переживают перезагрузку. Кнопка со счётчиком рядом с карандашом открывает список: «Скопировать всё для чата» собирает все замечания одним текстом с экраном, маршрутом и путём до элемента. Код: `src/Feedback.tsx`, стили `fb-*` в `src/ds/ds.css`.

## Запуск

Из папки `frontend` (Node.js 22.12+ либо совместимая более новая версия):

```sh
npm ci
npm run dev:demo
```

Открыть `http://localhost:5173`. Демо явно помечено в шапке; данные живут в памяти вкладки и сбрасываются при перезагрузке. Внешние провайдеры не вызываются. Выбор роли в демо позволяет пройти сценарии студента, ревьюера и координатора.

Для реального REST:

```sh
cp .env.example .env.local
npm run dev
```

`BACKEND_URL` по умолчанию `http://127.0.0.1:18000`, как в `deploy/compose.yaml`. Vite проксирует `/api` без удаления префикса. Браузер обращается к одному origin и использует HttpOnly session cookie; секреты и actor не передаются из JavaScript. В обычном режиме нет автоматической подмены ответа демо-данными. `VITE_*` переменные не нужны.

Две команды запуска используют один порт: завершите одну перед запуском другой. Обычная production-сборка `npm run build` исключает demo transport из JS. Для размещения собранной SPA нужны same-origin reverse proxy `/api` к backend, TLS и выдача `index.html`; Vite preview не заменяет production proxy.

## Что подключено

| Макеты | Рабочий сценарий и маршрут фронтенда | Граница |
|---|---|---|
| Р1 — вход | Stepik; magic-link reviewer; локальный стенд; выход из сессии | По действующему контракту вместо Avito ID из макета |
| Р2 — курсы | `#/courses`, `#/courses/:courseRunId` | Реальные курсы, потоки, задания; без выдуманных счётчиков |
| Р3 — доступность | `#/preferences` | Выбор потоков и плановые минуты; текущие предпочтения API не возвращает, форма явно задаёт новые |
| Р2 — мои работы и пул | `#/works`, `#/pool` | Активные проверки и общий пул, «Взять» и «Вернуть в пул» |
| Р3, Р4 — кабинет | `#/preferences`, `#/statistics` | Курсы, отсутствие, уведомления; статистика за период |
| Р5, Р6 — карточка работы | `#/reviews/:reviewIterationId` | Разбор от модели по требованиям со шкалой, признаки ИИ, ответ студенту, итог, вкладки попыток; сохранение и публикация с подтверждением |
| С1 — сдача | `#/submit/:courseRunId/:courseRunHomeworkId` | GitHub / Google Docs → preflight → submit; файлового upload нет |
| С2 — саморевью | Не включено | Контракт не содержит студенческого саморевью |
| С3, С5 — попытки и результат | `#/submissions/:submissionId` | Версии, capture status и опубликованный отзыв; новая сдача через исходную страницу задания |
| С4 — мои домашки | Курсы + `#/open` для ссылки на свою работу | Списка всех submission пользователя API не предоставляет |
| К1–К3 — каталог курсов/заданий | `#/courses`, `#/courses/:courseRunId`, `#/homework/:homeworkId?run=:courseRunId` | Курсы, импорт из Stepik, опубликованные задания, создание задания и версии, публикация в потоке |
| К4–К5 — редактор задания | `#/homework/:homeworkId?run=:courseRunId` | Текст, критерии, максимальные баллы, формат, время проверки, дедлайны. Эталон, шкалы и калибровка из старого макета не добавляются в закрытый контракт |
| К6–К7 — аналитика и реестр | Доступны участники потока, `#/people`, `#/deliveries` | Аналитики, полного реестра сдач, напоминаний и переназначения на другого ревьюера в REST нет |
| К8 — просмотр ревью | `#/reviews/:reviewIterationId` в роли координатора | Только чтение, как в макете |
| К9 — выгрузка | Не включено | Нет маршрута экспорта |
| Дополнительно | `#/operations/:operationId`, `#/people`, `#/deliveries` | Операции, роли участников, приглашения/отзыв, независимые статусы доставок |

В демо: курсы → поток → «Следующая работа» → «Открыть проверку» → заполнить баллы и обоснование → сохранить → опубликовать → подтвердить. В роли студента: курсы → задание → проверить ссылку → сдать → посмотреть попытку. Координатор может создать и опубликовать новую версию задания и работать с приглашениями. Demo-импорт отвечает явным 501; он требует настоящего backend adapter.

У agent/MCP нет экранов или навигации. Frontend не вызывает внутренние AI-events, MCP, выдачу агентских прав или provider API.

## Блокеры реального сквозного запуска

Проверка текущего backend выполнена 2026-09-05, после checkpoint `6a3398c`; параллельная backend-задача продолжает работу. Наличие маршрутов и зелёные контрактные тесты не доказывают, что браузерная сессия подключена к runtime.

1. `backend/src/review_platform/api/routes/identity_courses.py::_actor` и остальные resource routes читают `request.state.request_actor`. В просмотренном `main.py` и middleware отсутствует связка session cookie → `RequestActor`. `/v1/session` проверяет cookie отдельно. Нужна серверная аутентификация запроса; frontend не подставляет actor/header и не обходит авторизацию.
2. Auth routes зависят от `app.state.installation_organization_id`, Stepik bindings/redirect/authorization URL и прочих server-owned auth параметров. Их production composition в просмотренном `main.py` не подключена. Нужны штатный bootstrap и локальный provider adapter. Приложение не создаёт учётные записи в обход штатного входа.
3. Backend выдаёт cookie с `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/api`. Для реальной браузерной проверки нужен HTTPS либо корректно поддерживаемый браузером localhost secure-context; атрибуты cookie фронтенд не ослабляет.
4. Stepik callback реализован как POST с `code` и `state` в query, хотя в замороженном OpenAPI эти параметры не описаны. Frontend поддерживает этот фактический handler: OAuth redirect должен вести на страницу приложения с указанными параметрами, пользователь завершает вход, после успеха query удаляется. Настройка live OAuth не выполнялась.
5. `DeliverySummary` не содержит ревизии, обязательной для `retry_delivery`. Поэтому UI показывает статусы и историю, но не отправляет повтор с выдуманной ревизией.
6. `ReviewDetail` содержит IDs версий, но не полный snapshot критериев. UI получает опубликованные задания потока и истории, выбирая точный `homework_version_id`. Если эта версия недоступна, сохранение отключено; подмена на последние критерии запрещена.

Backend-файлы не менялись, чтобы не пересекаться с активной задачей. Сквозной запуск с настоящей сессией и live-провайдерами остаётся непроверенным. Эти пункты нужно перепроверить после завершения backend composition/gates.

## Контракты и проверки

```sh
npm run generate:api
npm run check:api
npm test
npm run build
npm run format:check
```

Генератор читает исходные frozen OpenAPI/JSON Schema: `src/api/schema.ts` — response types, `commands.ts` — payload types/revision targets, `routes.ts` — HTTP методы/пути/типы результатов. `contract-hash.txt` фиксирует SHA-256 обоих исходных контрактов. Проверка `check:api` падает при расхождении с исходниками. Ограничения длины массивов остаются в JSON Schema; generated TypeScript использует обычные массивы для редактируемых форм.

Команды включают `request_id`, `idempotency_key`, точный `expected_revision`. После потерянного/нечитаемого ответа повтор того же действия в текущей вкладке использует тот же wire body; автоматических повторов POST нет. После перезагрузки вкладки сначала проверьте серверный результат. Успешный ответ завершает receipt. 409 сохраняет введённый текст и показывает конфликт; 401 закрывает рабочее пространство. Наблюдение операций прекращается после терминального результата, ошибки и размонтирования. AI не заменяет человеческие решения автоматически.

Тесты проверяют frozen wire/response schemas, preflight/submit, save/publish, одноразовое подтверждение публикации, истечение сессии без цикла повторного входа, ограничения ролей, 409 без потери текста, сетевые ошибки/нечитаемый ответ, ключ повтора и завершение polling. Это тесты клиента и demo adapter, а не проверка настоящего provider runtime. Визуальный browser QA не проводился.

Подтверждённая локальная проверка: 17 тестов прошли; TypeScript, production build, `check:api`, форматирование — успешно. HTTP smoke dev-сервера: `/`, `/src/App.tsx`, `/demo-artifact.txt` ответили 200.

# Агент оценки домашних работ: ранжирование по силе

> Это исследовательский стенд от 4 сентября. Рабочее ядро проверки, которое вызывает платформа, живёт в [`prereview/`](../prereview/), описание в [`docs/AI_CORE.md`](../docs/AI_CORE.md).

Стенд для проверки того, умеет ли LLM-оценщик отличать сильную работу от слабой.
Разбор и результаты — в [`docs/GRADING_EXPERIMENT.md`](../docs/GRADING_EXPERIMENT.md).

**Коротко: не умеет заметно лучше, чем подсчёт символов.** Лучшая конфигурация
даёт 76,8 % попарной точности против 71,4 % у базовой линии «кто длиннее, тот
лучше», и разница в пределах шума. Стенд нужен, чтобы это было видно, а не
пряталось за красивым отчётом.

## Данные

`ai-talent-hub-avito/homework_examples` — 20 заданий, 58 решений с метками
слабое / среднее / хорошее. Клонировать рядом в `hw_examples/`.

## Запуск

```bash
git clone https://github.com/ai-talent-hub-avito/homework_examples hw_examples

python3 grader/manifest.py hw_examples   # опись заданий
python3 grader/bundle.py                 # docx/pdf/xlsx/ipynb/html -> текст
python3 grader/blind.py                  # слепой набор (метки прячутся)

export GRADER_API_KEY=...                # DeepSeek или любой OpenAI-совместимый
export GRADER_BASE_URL=https://api.deepseek.com/v1
export GRADER_MODEL=deepseek-chat

python3 grader/bench.py                  # наивный + структурный протоколы

# лучшая конфигурация: сравнение по всем работам + структурная усадка
GRADER_BLIND=grader/blind_full GRADER_CONDENSE=1 GRADER_CAP=40000 \
GRADER_TAG=condensed GRADER_OUT=grader/preds/condensed.json \
  python3 grader/ablate.py
```

`python3 grader/eval.py --length` — базовая линия по объёму.
`python3 grader/eval.py grader/preds/condensed.json` — метрики конфигурации.
Флаг `--reveal` показывает эталонный порядок; **по умолчанию он скрыт**, иначе
следующий прогон перестаёт быть слепым (мы на этом уже обожглись).

## Результаты

| метод | pairwise | exact | лучшая | худшая | совпадение с длиной |
|---|---|---|---|---|---|
| «длиннее = лучше» | 71,4 % | 45 % | 65 % | 55 % | 100 % |
| наивный: балл 0–100 по одной работе | 73,2 % | 45 % | 65 % | 65 % | 69,6 % |
| структурный: доказательства → сравнение | 66,1 % | 35 % | 60 % | 50 % | 73,2 % |
| сравнение по полным текстам | 69,6 % | 45 % | 60 % | 65 % | 66,1 % |
| **сравнение + структурная усадка** | **76,8 %** | 45 % | **70 %** | 65 % | 80,4 % |

Случайно: pairwise 50 %, exact 17 %, лучшая/худшая 33 %.
n = 56 информативных пар; различия в 3–7 п.п. незначимы.

## Модули

| файл | что делает |
|---|---|
| `extract.py` | docx/pdf/xlsx/ipynb/html/код → текст; детект PDF без текстового слоя |
| `condense.py` | усадка под лимит контекста с сохранением структуры и пометками пропусков |
| `inventory.py` | программный подсчёт скриншотов, диаграмм, таблиц, тестов, чисел |
| `manifest.py` / `bundle.py` / `blind.py` | сборка и обезличивание набора |
| `prompts.py` | промпты стадий: рубрика → доказательства → сравнение |
| `run.py` | пайплайн: рубрика, цитаты, сравнительное судейство, аудит |
| `ablate.py` | сравнение по полным текстам (обход бутылочного горлышка) |
| `audit.py` | контроль смещений: объём и порядок подачи |
| `sandbox.py` / `codecheck.py` | обезличенные копии кода, прогон тестов и conformance |
| `eval.py` / `bench.py` | метрики ранжирования и полный прогон |

## Чему стенд научил

1. **Обрезка «первые N символов» — систематическая ошибка.** Она била по
   24 % работ в 9 заданиях из 20 и на одном задании инвертировала ранжирование
   целиком. Замена на структурную усадку дала больший прирост, чем любая
   правка промпта.
2. **Сжатие перед финальным суждением стоит дорого.** Стадия сравнения,
   получавшая только таблицу доказательств (14 % исходного текста), работала
   хуже наивного протокола.
3. **Запрет в промпте «не оценивай объём» не работает.** У конфигурации с этим
   запретом совпадение с базовой линией по длине выросло, а не упало.
4. **Абсолютный балл воздерживается.** Наивный протокол ставит равные баллы на
   25 % пар; там, где высказывается, он прав в 78,6 % случаев.
5. **Часть критериев проверяется только запуском.** Conformance-тест из ТЗ
   показал нарушение контракта ответа у двух работ из трёх — чтением это
   надёжно не видно.

# Feature Specification: Интеграция со Stepik

**Feature Branch**: backend

**Created**: 2026-09-04

**Status**: Draft — автоматическая запись требует live feasibility gate на платном или Enterprise-курсе

**Input**: Импорт курса и студентов, вход через Stepik, связь домашнего задания и обратная запись балла и текстового отзыва

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Подключить курс и импортировать студентов (Priority: P1)

Методист указывает ссылку на курс, входит через Stepik и получает в нашей платформе курс и доступный список зачисленных студентов.

**Why this priority**: Без курса и состава невозможно безопасно дать студентам доступ к заданиям.

**Independent Test**: Подключить тестовый курс с двумя студентами, повторить импорт и проверить отсутствие дублей.

**Acceptance Scenarios**:

1. **Given** корректная ссылка и методист с нужными правами, **When** он подключает курс, **Then** платформа показывает найденный курс и доступный состав до подтверждения импорта.
2. **Given** подтверждённый импорт, **When** он завершается, **Then** создаются курс, внешняя связь и студенческие членства.
3. **Given** курс уже подключён, **When** импорт повторяется, **Then** существующие записи обновляются без дублей.
4. **Given** Stepik возвращает демонстрационный или недоступный состав, **When** выполняется preflight, **Then** подключение помечается неполным и не выдаёт демонстрационным пользователям доступ.

---

### User Story 2 — Войти и получить доступ студенту (Priority: P2)

Студент переходит по ссылке со Stepik, входит через Stepik OAuth и получает доступ только к импортированным курсам, где его ID присутствует в составе.

**Why this priority**: Ручной ввод ID или email не доказывает владение Stepik-аккаунтом.

**Independent Test**: Войти за импортированного и неимпортированного пользователя и сравнить доступ.

**Acceptance Scenarios**:

1. **Given** Stepik ID присутствует в импортированном составе, **When** студент входит через Stepik, **Then** локальный пользователь связывается с этим ID и получает курс.
2. **Given** Stepik ID отсутствует в составе, **When** пользователь открывает ссылку задания, **Then** доступ к курсу не предоставляется.
3. **Given** пользователь уже связан со Stepik ID, **When** он входит повторно, **Then** используется существующая учётная запись.
4. **Given** один студент участвует в нескольких импортированных курсах, **When** он входит, **Then** он видит все соответствующие курсы без дублирования аккаунта.

---

### User Story 3 — Передать балл и текстовый отзыв (Priority: P3)

После публикации локального ревью платформа отправляет в связанный оцениваемый шаг Stepik актуальный процент и текстовый feedback.

**Why this priority**: Методист не должен вручную переносить каждый результат между системами.

**Independent Test**: Отправить балл тестовому студенту, дождаться завершения обработки, затем опубликовать изменённый балл и проверить обновление.

**Acceptance Scenarios**:

1. **Given** опубликованное ревью и рабочая связь с оцениваемым шагом, **When** создаётся доставка, **Then** Stepik получает Stepik ID, процент оценки и текстовый feedback.
2. **Given** Stepik принял файл, но ещё обрабатывает его, **When** пользователь смотрит доставку, **Then** она остаётся в состоянии обработки.
3. **Given** Stepik успешно обработал результат, **When** статус обновляется, **Then** доставка отмечается успешной и хранит подтверждение обработки.
4. **Given** опубликована новая итерация ревью, **When** его доставка завершается, **Then** новый балл заменяет предыдущий результат того же студента.
5. **Given** старая доставка возобновилась позже новой, **When** система обнаруживает устаревшую версию, **Then** старый балл не отправляется.

---

### User Story 4 — Восстановиться после ограничения Stepik (Priority: P4)

Если тариф, права или временная ошибка не позволяют автоматическую запись, методист видит причину и получает подготовленный файл для ручной загрузки.

**Why this priority**: Ограничение внешней платформы не должно терять опубликованные результаты.

**Independent Test**: Отключить возможность автоматической оценки, опубликовать ревью и скачать корректный fallback-файл.

**Acceptance Scenarios**:

1. **Given** курс не поддерживает автоматическую запись баллов, **When** методист завершает настройку, **Then** платформа заранее показывает ограничение и ручной режим.
2. **Given** результат опубликован в ручном режиме, **When** доставка создаётся, **Then** методист может получить файл Stepik с актуальными оценкой и feedback.
3. **Given** временная ошибка Stepik, **When** она исчезает, **Then** автоматическая доставка повторяется без дублирования результата.
4. **Given** права методиста отозваны, **When** синхронизация запускается, **Then** платформа показывает действие повторного подключения.

### Edge Cases

- URL ведёт не на курс или содержит лишние параметры.
- OAuth-пользователь не входит в команду курса.
- Курс бесплатный и возвращает демонстрационный gradebook.
- Один Stepik ID уже связан с локальным пользователем.
- Студент удалён из курса после сдачи.
- Состав меняется во время постраничного импорта.
- Оцениваемый шаг удалён или его максимальный балл изменён.
- Процент содержит дробное значение.
- Feedback содержит кириллицу, запятые, кавычки или переносы строк.
- В файл попал неизвестный Stepik ID.
- Stepik принял файл, но долго не завершает обработку.
- Повторная доставка старой итерации ревью запускается после новой.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Методист MUST иметь возможность подключить курс по Stepik URL через собственную OAuth-сессию.
- **FR-002**: Платформа MUST проверить доступ методиста к курсу до импорта.
- **FR-003**: Платформа MUST показать найденный курс и состояние доступных возможностей до подтверждения.
- **FR-004**: Импорт MUST получать всех доступных зачисленных студентов и обходить весь постраничный результат.
- **FR-005**: Платформа MUST распознавать демонстрационный состав и MUST NOT создавать по нему реальные членства.
- **FR-006**: Повторный импорт MUST обновлять существующие связи без дублирования курса или студентов.
- **FR-007**: Синхронизация MUST различать нового, сохранившего членство и удалённого из состава студента.
- **FR-008**: Stepik ID MUST быть стабильным внешним идентификатором пользователя.
- **FR-009**: Студент MUST подтверждать владение Stepik ID через OAuth, а не ручным вводом.
- **FR-010**: Вход через Stepik MUST предоставлять доступ только к курсам, где найдено соответствующее членство.
- **FR-011**: Один локальный пользователь MUST иметь возможность состоять в нескольких Stepik-курсах.
- **FR-012**: Методист MUST иметь возможность связать локальное задание с существующим оцениваемым шагом Stepik.
- **FR-013**: Связь MUST хранить максимальный балл и MUST обнаруживать его изменение снаружи.
- **FR-014**: Автоматическая запись MUST использовать шаг, поддерживающий оценки внешних работ.
- **FR-015**: Публикация результата MUST преобразовать локальный итог в процент от максимума Stepik.
- **FR-016**: Правило округления MUST быть единым, видимым и воспроизводимым.
- **FR-017**: В Stepik MUST передаваться текстовый feedback; полный локальный отзыв MUST сохраняться независимо.
- **FR-018**: Доставка MUST различать ожидание, обработку, успех, повторимую ошибку и требуемое действие.
- **FR-019**: Успех MUST фиксироваться только после подтверждённого завершения обработки Stepik без ошибки.
- **FR-020**: Новая публикация MUST обновлять результат студента и MUST NOT уничтожать локальную историю итераций ревью.
- **FR-021**: Устаревшая доставка MUST NOT заменять более новый балл.
- **FR-022**: Повтор одной логической доставки MUST NOT создавать дублирующий текущий результат.
- **FR-023**: При недоступной автоматической записи платформа MUST сформировать совместимый файл ручной загрузки.
- **FR-024**: Ручной режим MUST оставлять доставку незавершённой, пока методист не отметит результат перенесённым.
- **FR-025**: Платформа MUST показывать методисту ограничения тарифа, прав и внешнего шага до массовой публикации.
- **FR-026**: Повторное подключение OAuth MUST восстанавливать синхронизацию без пересоздания курса.
- **FR-027**: Каждая операция импорта и доставки MUST иметь диагностируемое состояние, время, число попыток и очищенную ошибку.
- **FR-028**: OAuth-полномочия одной организации MUST NOT использоваться для курса другой организации.

### Key Entities

- **Stepik Account Binding**: связь пользователя с подтверждённым Stepik ID.
- **Stepik Course Binding**: связь локального курса с внешним курсом и подключившим методистом.
- **Imported Student Membership**: последнее известное участие Stepik ID в курсе.
- **Stepik Grade Binding**: связь домашнего задания с оцениваемым шагом и его шкалой.
- **Course Import Run**: один запуск импорта, его прогресс и результат.
- **Grade Delivery**: передача одной версии балла и feedback в Stepik.
- **Manual Grade Export**: файл для fallback-переноса результатов методистом.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Методист с подходящими правами подключает курс и видит импортированный состав не более чем за 5 минут.
- **SC-002**: Повторный импорт одного состава создаёт 0 дубликатов пользователей и членств.
- **SC-003**: В приёмочном тесте 100% демонстрационных пользователей бесплатного курса отклоняются как реальные участники.
- **SC-004**: 100% импортированных студентов получают доступ после входа через правильный Stepik-аккаунт, а неизвестные ID доступа не получают.
- **SC-005**: Методист видит ограничение автоматической записи до публикации первого результата.
- **SC-006**: Успешно обработанный тестовый балл и текстовый feedback становятся видны студенту Stepik.
- **SC-007**: Повторная публикация обновляет тестовый балл вверх и вниз без потери локальной истории.
- **SC-008**: Повтор одной логической доставки не создаёт второго текущего результата.
- **SC-009**: При временной ошибке локальный отзыв остаётся доступным, а доставка автоматически восстанавливается или становится видимым исключением.
- **SC-010**: Для любого опубликованного результата методист может получить совместимый файл ручной загрузки.

## Assumptions

- Основной целевой курс предоставляет реальный gradebook и поддерживает manual-score.
- Методист подключает аккаунт с правами команды курса.
- Stepik OAuth подтверждает личность, а импортированный roster подтверждает доступ к курсу.
- Локальное ревью является источником истины; Stepik хранит внешнее отображение актуального результата.
- В автоматическом режиме отправляется целочисленный процент от 0 до 100.
- Feedback для Stepik ограничивается одним текстовым резюме и ссылкой на полный локальный отзыв.
- Поддержка LTI и штатного instructor review не входит в эту функцию.
- Конкретные HTTP-операции и правила повторов определяются на этапе технического планирования и проверяются на тестовом платном или Enterprise-курсе.

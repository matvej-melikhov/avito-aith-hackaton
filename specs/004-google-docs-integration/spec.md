# Feature Specification: Интеграция с Google Docs

**Feature Branch**: backend

**Created**: 2026-09-04

**Status**: Draft

**Input**: Сдача Google Docs по доступной ссылке, экспорт DOCX, фиксация проверенной версии и обработка потери доступа

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Проверить ссылку и доступ (Priority: P1)

Студент включает чтение документа по ссылке, вставляет URL и до отправки видит, может ли платформа получить нужный Google Docs файл.

**Why this priority**: Недоступный или неверный документ не должен попадать в очередь ревьюера.

**Independent Test**: Проверить документ с доступом по ссылке, закрытый документ, удалённый документ и ссылку на другой тип Drive-файла.

**Acceptance Scenarios**:

1. **Given** Google Docs с чтением по ссылке, **When** студент проверяет URL, **Then** платформа показывает имя документа и разрешает отправку.
2. **Given** закрытый или domain-only документ, **When** ссылка проверяется, **Then** платформа сообщает, что нужен доступ по ссылке.
3. **Given** ссылка содержит resource key, **When** документ проверяется и экспортируется, **Then** ключ сохраняется и передаётся в публичный export URL.
4. **Given** ссылка ведёт на удалённый, скрытый или неподдерживаемый файл, **When** выполняется preflight, **Then** сдача отклоняется с понятной причиной.

---

### User Story 2 — Получить и сохранить DOCX-версию (Priority: P2)

При начале проверки платформа экспортирует актуальный документ в DOCX, проверяет полученный файл и сохраняет точную версию, которую увидит ревьюер.

**Why this priority**: Живой документ может меняться, поэтому результат должен ссылаться на воспроизводимое содержимое.

**Independent Test**: Экспортировать тестовый документ с текстом, таблицей и изображением, проверить OOXML и повторить импорт после изменения.

**Acceptance Scenarios**:

1. **Given** доступный одновкладочный Google Docs, **When** начинается ревью, **Then** платформа сохраняет валидный DOCX и его контрольную сумму.
2. **Given** экспорт вернул пустой или повреждённый файл, **When** выполняется проверка, **Then** версия не создаётся и показывается ошибка экспорта.
3. **Given** экспорт превышает ограничение провайдера, **When** операция завершается ошибкой, **Then** студент видит, что документ слишком велик для этого способа сдачи.
4. **Given** документ изменился после предыдущего импорта, **When** создаётся новая версия, **Then** она получает другую контрольную сумму, а старая остаётся доступной.
5. **Given** Google Docs содержит несколько вкладок, **When** студент отправляет его в MVP, **Then** платформа предупреждает, что поддерживается одна вкладка, и не обещает полноту многовкладочного экспорта.

---

### User Story 3 — Обнаружить изменение во время ревью (Priority: P3)

Перед публикацией платформа сравнивает текущие метаданные с сохранённой версией. Ревьюер может завершить старый DOCX или попросить студента явно отправить новую версию.

**Why this priority**: Студент и ревьюер не должны незаметно работать с разным содержимым.

**Independent Test**: Изменить документ после начала ревью, завершить зафиксированную версию, затем явно отправить новую и открыть отдельную итерацию ревью.

**Acceptance Scenarios**:

1. **Given** документ не изменился, **When** ревьюер публикует результат, **Then** отзыв связывается с сохранённым DOCX.
2. **Given** документ изменился, **When** ревьюер пытается публиковать, **Then** платформа показывает изменение до завершения.
3. **Given** документ изменился после дедлайна, **When** нужна проверка новой версии, **Then** студент явно отправляет её, после чего ревьюер или методист открывает новую итерацию ревью.
4. **Given** ревьюер выбирает старую версию, **When** результат публикуется, **Then** в истории явно указан хеш проверенного DOCX.
5. **Given** студент только редактирует Google Docs, **When** нет явной новой сдачи, **Then** отдельная повторная итерация ревью автоматически не создаётся.

---

### User Story 4 — Обработать потерю доступа (Priority: P4)

Если автор закрыл или удалил документ, платформа показывает ошибку доступа. Ранее сохранённые DOCX-версии и опубликованные отзывы остаются доступны.

**Why this priority**: Отзыв доступа не должен уничтожать историю уже выполненной проверки.

**Independent Test**: Отозвать доступ после импорта, повторить чтение и открыть сохранённую версию.

**Acceptance Scenarios**:

1. **Given** доступ отозван до первого импорта, **When** студент отправляет ссылку, **Then** сдача не принимается.
2. **Given** доступ отозван после создания версии, **When** выполняется новая проверка, **Then** платформа показывает ошибку, но сохраняет старый DOCX.
3. **Given** доступ восстановлен, **When** пользователь повторяет проверку, **Then** платформа может получить актуальную версию без пересоздания сдачи.
4. **Given** локальное ревью опубликовано, **When** исходный Google Docs удалён, **Then** отзыв и проверенный снимок остаются доступны по правилам хранения.

### Edge Cases

- URL не принадлежит Google Docs или содержит неверный document ID.
- В ссылке отсутствует нужный resource key.
- Доступ открыт только домену автора.
- Организационная политика запрещает скачивание.
- Файл находится на shared drive.
- Ссылка ведёт на Google Sheets, Slides, PDF или бинарный DOCX.
- Документ находится в корзине.
- Метаданные изменились между preflight и export.
- Экспорт пуст, повреждён или превышает 10 MB.
- DOCX содержит внешние ссылки на изображения.
- Документ содержит несколько или вложенные вкладки.
- Comments, suggestions или drawings не попали в DOCX.
- Качество экспортированного изображения снизилось.
- Доступ отозван во время ревью.
- Один и тот же документ сдан несколькими студентами.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Платформа MUST принимать Google Docs URL и MUST NOT принимать другие типы Drive-файлов в MVP.
- **FR-002**: Студент MUST предоставить чтение документа по ссылке до отправки.
- **FR-003**: Платформа MUST проверить, что публичный DOCX-export доступен, непуст и возвращает допустимый тип содержимого.
- **FR-004**: Платформа MUST сохранять document ID и присутствующий в ссылке resource key.
- **FR-005**: Resource key MUST сохраняться и использоваться в публичном export URL одного документа.
- **FR-006**: Ошибка доступа MUST объяснять студенту необходимость открыть чтение по ссылке.
- **FR-007**: Платформа MUST безопасно объединять недоказуемые причины в «файл не найден или нет доступа» и отдельно различать только подтверждённые состояния: неверный тип, корзина, запрещённое скачивание, слишком большой или повреждённый экспорт.
- **FR-008**: При начале ревью платформа MUST получить актуальный DOCX через доступный Drive export.
- **FR-009**: Успешный экспорт MUST быть непустым валидным OOXML-документом.
- **FR-010**: Платформа MUST применять ограничение провайдера в 10 MB к результату экспорта.
- **FR-011**: Метаданные размера MUST NOT использоваться как единственное доказательство допустимого размера DOCX.
- **FR-012**: Сохранённая версия MUST включать исходный URL, document ID, время, DOCX-байты, размер, media type и SHA-256.
- **FR-013**: Одна итерация ревью MUST ссылаться на одну сохранённую DOCX-версию.
- **FR-014**: Предыдущая версия MUST сохраняться после нового экспорта.
- **FR-015**: MVP MUST явно ограничивать поддержку Google Docs одной вкладкой.
- **FR-016**: Платформа MUST NOT заявлять, что DOCX гарантированно сохраняет comments, suggestions, drawings, все изображения или несколько вкладок.
- **FR-017**: Ревьюер MUST иметь доступ к исходной ссылке и сохранённому DOCX.
- **FR-018**: Перед публикацией платформа MUST повторить публичный DOCX-export и сравнить SHA-256 с версией итерации ревью.
- **FR-019**: При изменении текущая итерация ревью MUST сохранять свой DOCX; новая версия MUST пройти явную сдачу студента и отдельное открытие итерации ревью.
- **FR-020**: Обновление снимка MUST быть явно отражено в истории итерации ревью.
- **FR-021**: Изменение Google Docs MUST NOT само создавать новую итерацию ревью.
- **FR-022**: Новая итерация ревью MUST возникать только после явной новой сдачи и действия ревьюера или методиста.
- **FR-023**: Обратная связь MUST храниться в нашей платформе и MUST NOT публиковаться в Google Docs.
- **FR-024**: Потеря доступа MUST становиться видимым состоянием и MUST NOT удалять сохранённый DOCX или отзыв.
- **FR-025**: После восстановления доступа пользователь MUST иметь возможность повторить preflight или экспорт.
- **FR-026**: Повтор одной операции импорта MUST NOT создавать дублирующую версию с тем же содержимым.
- **FR-027**: Все проверки и экспорты MUST иметь время, попытки, очищенную ошибку и доступные метаданные для диагностики.
- **FR-028**: Полномочия Google одной организации MUST NOT использоваться для документов другой организации.
- **FR-029**: Срок хранения DOCX MUST следовать общей политике артефактов backend core.
- **FR-030**: Разбор содержимого DOCX и AI-review MUST оставаться за границей этой функции.

### Key Entities

- **Google Docs Artifact Reference**: исходный URL, document ID и resource key.
- **Drive Access Preflight**: тип, доступность, возможность скачивания и состояние файла.
- **Google Docs Artifact Version**: сохранённый DOCX, SHA-256, размер, media type и время получения.
- **Google Docs Change Signal**: обнаруженное расхождение внешней и проверенной версии.
- **Google Docs Import Attempt**: одна проверка или экспорт с состоянием и ошибкой.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% доступных одновкладочных Google Docs fixtures проходят preflight и создают валидный DOCX.
- **SC-002**: 100% закрытых, недоступных, удалённых и неподдерживаемых fixtures отклоняются до активного ревью с безопасной доказуемой категорией ошибки.
- **SC-003**: Документ в пределах ограничений становится доступен ревьюеру не более чем за 2 минуты.
- **SC-004**: Каждый успешный снимок имеет проверяемый SHA-256 и может быть повторно открыт без Google Docs.
- **SC-005**: В контролируемых fixtures изменение метаданных обнаруживается при проверке перед публикацией; сохранённый DOCX остаётся единственным авторитетным содержимым итерации ревью.
- **SC-006**: Повтор импорта неизменившегося документа не создаёт дублирующего содержимого.
- **SC-007**: Отзыв доступа не удаляет ни одного ранее сохранённого DOCX или опубликованного отзыва.
- **SC-008**: Документы, чей экспорт превышает 10 MB, не исчерпывают место сверх настроенного защитного предела.
- **SC-009**: Для каждого импорта ревьюер или MCP-агент видит время, хеш, внешнюю версию и последнюю полезную ошибку.
- **SC-010**: Ни один приёмочный тест не использует comments, suggestions или многовкладочный контент как гарантированно сохранённое содержимое DOCX.

## Assumptions

- Студенты могут включить режим anyone with the link: reader.
- Публичный DOCX-export документа доступен без Google credentials.
- Работа находится в одной вкладке Google Docs.
- DOCX является авторитетным снимком содержимого, используемым в ревью.
- Исходная ссылка остаётся доступной ревьюеру, пока студент не отозвал доступ.
- Другие типы Google Drive не входят в MVP.
- Комментарии в Google Docs не являются каналом публикации обратной связи.
- Изменение документа является сигналом, а не новой сдачей.
- Срок хранения берётся из общей backend-политики и определяется при планировании.

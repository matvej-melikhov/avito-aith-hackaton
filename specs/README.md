# Спецификации

Два вида документов. Функциональные спецификации 001–005 написаны по шаблону spec-kit до кода и заморожены контрактами с fixtures: две половины команды работали против них на заглушках. Аналитические спецификации 006–011 написаны к финалу 7 сентября: в них разбор данных, интервью и замеров, варианты и принятое решение, требования со статусом в MVP и критерии успеха для пилота.

Все числа в спецификациях берутся из [docs/NUMBERS.md](../docs/NUMBERS.md), где каждое подписано как замер, источник или допущение.

## Функциональные спецификации и контракты

| Папка | О чём | Статус |
|---|---|---|
| [001-backend-core](001-backend-core/) | ядро платформы: организация, курсы, задания и версионируемые критерии, сдачи, итерации ревью, доставки, аудит, MCP. Контракты 1.1.0 с sha256 и fixtures | реализовано, контракты заморожены |
| [002-stepik-integration](002-stepik-integration/) | импорт курса и студентов, вход через Stepik, запись балла | черновик, живая запись требует проверки доступности API |
| [003-github-integration](003-github-integration/) | приём ссылок, снимок коммита, GitHub App | снимок реализован, публикация за воротами GitHub App |
| [004-google-docs-integration](004-google-docs-integration/) | экспорт docx, фиксация версии, потеря доступа | адаптер docx реализован |
| [005-workspace-completion](005-workspace-completion/) | контракт бэкенд ↔ сервис ИИ-проверки версии 2.0.0: самопроверка студента и помощь ревьюеру, события, идемпотентность | реализовано с обеих сторон |

## Как читать

Начинать с 006, оно объясняет, зачем остальное. Для защиты ядра проверки: 008 и 007. Для разговора про безопасность и внедрение: 009 и 010. Для координации: 011.
